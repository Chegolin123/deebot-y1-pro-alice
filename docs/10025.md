# Ошибка `(406,10025)`: разбор

## Симптом

Робот добавлен в Wi-Fi, получает адрес, виден в DHCP-клиентах роутера. Приложение
Ecovacs Home на финальном шаге показывает:

```
Код ошибки: DEEBOT Y1 PRO (406,10025)
Не удалось подключить робот-пылесос к сети — 【10010】、【10018】、【10025】
```

Коды `10010 / 10018 / 10025` в документации Ecovacs означают «робот не смог
подключиться к сети». Текст ошибки вводит в заблуждение: он про Wi-Fi, но Wi-Fi
в порядке.

## Что проверено и исключено

| Версия | Проверка | Итог |
| --- | --- | --- |
| Робот не в сети | DHCP-клиенты роутера: `Client Name: Livirobo`, адрес выдан | в сети |
| Не тот диапазон | `hwmode=802.11b/g/n`, канал 11, 20 МГц | верно |
| Слабое шифрование | `psk_version=rsn` (WPA2-PSK), `psk_cipher=aes` | верно |
| Ширина 40 МГц | `htmode` был `auto`, выставлен `20` | не влияло |
| Имя сети | пробелы и точка в SSID, переименовано | не влияло |
| VPN на телефоне | отключён при настройке | не влияло |
| DNS | `ecouser.net` резолвится одинаково через Яндекс, Google, Cloudflare и домашний DoH-мост | верно |

**Важно про MAC.** Приложение может показывать адрес с первым байтом `AA:…`, а в
таблице ARP устройство видно как `A8:…`. Разница — младший бит первого байта:
это тот же адрес с выставленным флагом локального администрирования
(рандомизация MAC). Не ищите робота в ARP по адресу из приложения.

## Доказательство

Логи DNS-сервера (`dnsmasq`) показывают цикл опроса раз в 5 секунд:

```
query[A] jmq2-ngiot-ru.dc.robotww.ecouser.net from <IP_РОБОТА>
reply   jmq2-ngiot-ru.dc.robotww.ecouser.net is NXDOMAIN
query[AAAA] jmq2-ngiot-ru.dc.robotww.ecouser.net from <IP_РОБОТА>
reply   jmq2-ngiot-ru.dc.robotww.ecouser.net is NODATA-IPv6
```

Имя не существует в зоне: `dig` возвращает `status: NXDOMAIN` с SOA зоны
`ecouser.net` в authority — одинаково у `77.88.8.8` (Яндекс), `8.8.8.8` (Google)
и `1.1.1.1` (Cloudflare).

Живые соседние имена:

```
jmq2-ngiot-eu.dc.robotww.ecouser.net → 46.243.226.152, 87.242.122.151
jmq-ngiot-ru.dc.ww.ecouser.net       → 37.230.195.108
portal-ru.ecouser.net                → 46.243.143.85
api-app.dc-ru.ww.ecouser.net         → 131.222.134.12
```

То есть **RU-эндпоинт старой схемы (`jmq2 … .dc.robotww.`) выведен из
эксплуатации**, а прошивка продолжает в него стучаться.

## Решение

1. Зарегистрировать аккаунт Ecovacs Home с регионом **Poland** (любая страна ЕС).
2. Сбросить Wi-Fi на роботе: короткое нажатие Reset (~1 с) до мигания индикатора;
   если не помогает — выключить и включить питание.
3. Привязать робота к сети 2.4 ГГц, телефон — в той же сети, мобильные данные
   выключены.

После этого в логах видно переключение:

```
jmq2-ngiot-eu.dc.robotww.ecouser.net → 8.211.113.136 / .143 / .132
api-base.robotww.ecouser.net         → 47.251.241.125
ca.robotww.ecouser.net               → 47.87.137.165
```

Опросы прекращаются — робот подключился.

> Цена: интерфейс приложения и голосовые подсказки — на английском;
> Yandex Alice через официальный навык перестаёт видеть робота (он и так его
> не поддерживал), поэтому нужен свой провайдер — см. корневой README.

## Резервный вариант

Если EU-эндпоинт когда-нибудь тоже умрёт, мёртвое имя можно перенаправить на
живой сервер по DNS. TLS это позволяет: SLB отдаёт сертификат
`CN=*.ecouser.net` с SAN, включающим `*.dc.robotww.ecouser.net`.

Пример для `dnsmasq`:

```
address=/jmq2-ngiot-ru.dc.robotww.ecouser.net/37.230.195.108
```

Сервер отвечает на 8883 и 443. Этот путь не проверялся в бою — он оставлен как
аварийный.

## Хронология проверки

Полезно как метод: сначала исключается Wi-Fi (ассоциация, DHCP), затем DNS,
затем выясняется, куда именно обращается устройство. Решающим шагом был не
перебор настроек роутера, а **просмотр DNS-логов по IP робота**: он показал
конкретное имя, а `dig` по нему — что имени нет ни у одного резолвера.

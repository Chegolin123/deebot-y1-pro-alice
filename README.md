# DEEBOT Y1 Pro → Яндекс «Дом с Алисой»

Управление роботом-пылесосом **Ecovacs DEEBOT Y1 Pro** голосом через Алису, когда
официальный навык Ecovacs этого не умеет.

Проект состоит из трёх частей, каждая решает свою проблему:

1. **Диагноз `(406,10025)`** — почему робот не привязывается к аккаунту в России
   и что с этим делать ([docs/10025.md](docs/10025.md)).
2. **Мост в Яндекс** (`bridge/`) — FastAPI-сервис, реализующий протокол
   «Умного дома» Яндекса поверх библиотеки `deebot-client`.
3. **Проба** (`probe/`) — read-only диагностика: показывает, виден ли робот,
   приходит ли телеметрия и где именно рвётся.

---

## Проблема

При добавлении робота приложение Ecovacs Home показывает:

```
Код ошибки: DEEBOT Y1 PRO (406,10025)
Не удалось подключить робот-пылесос к сети — 【10010】、【10018】、【10025】
```

При этом робот **уже в Wi-Fi**: получает DHCP-адрес и виден в списке клиентов
роутера. То есть проблема не в 2.4 ГГц, не в WPA2 и не в имени сети.

### Причина

Прошивка обращается к облачному эндпоинту по **старой схеме имён**:

```
jmq2-ngiot-ru.dc.robotww.ecouser.net   → NXDOMAIN
```

Этого имени больше нет в зоне `ecouser.net` — проверяется одинаково у
Яндекса, Google и Cloudflare (в authority приходит SOA зоны). Робот опрашивает
его каждые 5 секунд, приложение по таймауту показывает `10025`.

Живые эндпоинты на момент проверки (22.11.2026):

| Имя | Ответ |
| --- | --- |
| `jmq2-ngiot-ru.dc.robotww.ecouser.net` | **NXDOMAIN** |
| `jmq2-ngiot-eu.dc.robotww.ecouser.net` | 46.243.226.152, 87.242.122.151 |
| `jmq-ngiot-ru.dc.ww.ecouser.net` | 37.230.195.108 |
| `portal-ru.ecouser.net` | 46.243.143.85 |
| `api-app.dc-ru.ww.ecouser.net` | 131.222.134.12 |

### Решение

Зарегистрировать аккаунт Ecovacs Home с регионом **не Россия** (в нашем случае
Poland). Приложение выдаёт роботу живой эндпоинт, привязка проходит:

```
jmq2-ngiot-eu.dc.robotww.ecouser.net → 8.211.113.136 / .143 / .132
api-base.robotww.ecouser.net         → 47.251.241.125
ca.robotww.ecouser.net               → 47.87.137.165
```

> **Важно:** карта квартиры и зоны хранятся в облаке и привязаны к аккаунту.
> После того как робот привязан и карта построена, регион менять нельзя —
> карта потеряется.

---

## Почему нужен свой навык Алисы

Официальный навык «ECOVACS Robotics» в каталоге Яндекса:

- требует, чтобы аккаунт Ecovacs Home был зарегистрирован с регионом **«Россия»**;
- перечисляет поддерживаемые модели: `OZMO 950/900`, `T8/T8+/T8 AIVI`, `U2`, `600/605`.

Y1 Pro там нет, а RU-аккаунт теперь не работает вовсе. Поэтому мост
представляется Яндексу как **свой провайдер умного дома**.

## Архитектура

```
Алиса / «Дом с Алисой»
        │  HTTPS, протокол «Умного дома»
        ▼
   bridge (FastAPI, :8099)
        │  deebot-client (MQTT + REST)
        ▼
   облако Ecovacs (регион EU)
        │
        ▼
     DEEBOT Y1 Pro
```

Особенности реализации:

- **`kduunv` → `cqyi87`.** Робот представляется классом `kduunv`, которого нет в
  библиотеке. Он делит `UILogicId y30_ww_h_y30h5` с `cqyi87`, поэтому при сборке
  образа создаётся модуль-заглушка `hardware/kduunv.py`, реэкспортирующий профиль
  `cqyi87`.
- **`deebot-client` собирается из ветки PR #1869** (`Lalit-Patil-07/client.py`,
  `feat/y1-pro-device-support`), потому что в upstream поддержки Y1 Pro пока нет.
  PR закрыт по размеру — автор предлагал разбить его на части.
- **OAuth без внешнего провайдера.** `/auth/authorize` и `/auth/token` реализованы
  в самом сервисе; токен хранится в томе `/data`, поэтому перезапуск не разрывает
  уже привязанный навык.
- **Один пользователь.** Сервис рассчитан на личное использование: один аккаунт,
  одно устройство, один пароль на привязку.

## Быстрый старт

### 1. Сборка образа

```bash
docker build -t deebot-bridge ./bridge
```

Сборка тянет Rust-тулчейн и компилирует `deebot-client` — это несколько минут.

### 2. Конфигурация

```bash
cp bridge/bridge.env.example bridge/bridge.env
```

| Переменная | Назначение |
| --- | --- |
| `ECOVACS_EMAIL` | e-mail аккаунта Ecovacs Home (регион EU) |
| `ECOVACS_PASSWORD` | пароль аккаунта |
| `ECOVACS_COUNTRY` | `PL` — регион аккаунта |
| `ECOVACS_CLASS` | `kduunv` — класс устройства |
| `DEVICE_NAME` | имя в «Доме с Алисой», напр. `Пылесос` |
| `DEVICE_ROOM` | комната, напр. `Коридор` |
| `BRIDGE_PASSWORD` | пароль, который вы введёте один раз при привязке |
| `CAPABILITIES` | что отдавать Алисе: `on_off,toggle,mode` |
| `DATA_DIR` | каталог для токена, по умолчанию `/data` |

### 3. Запуск

```bash
docker run -d --name deebot-bridge \
  --env-file bridge/bridge.env \
  -v deebot-bridge-data:/data \
  -p 8099:8099 \
  deebot-bridge
```

Проверка: `curl http://127.0.0.1:8099/health`

### 4. Публикация наружу

Яндекс обращается к навыку по **HTTPS с валидным сертификатом**. Самоподписанный
не подойдёт. Нужен домен и reverse proxy, например:

```
https://deebot.example.com/  →  127.0.0.1:8099
```

### 5. Навык в Яндекс.Диалогах

1. Откройте <https://dialogs.yandex.ru/developer> и создайте диалог типа
   **«Умный дом»**.
2. Вкладка **Настройки**:
   - Backend: `https://deebot.example.com` (без `/v1.0`)
   - Тип доступа: **Приватный**
3. Вкладка **Связка аккаунтов** (OAuth):
   - Идентификатор приложения: `https://social.yandex.net/`
   - Секрет приложения: любое значение
   - URL авторизации: `https://deebot.example.com/auth/authorize`
   - URL получения токена: `https://deebot.example.com/auth/token`
   - URL обновления токена: `https://deebot.example.com/auth/token`
4. Опубликовать (для приватного навыка — мгновенно).
5. В приложении **«Дом с Алисой»** → «Устройство умного дома» → выбрать свой
   навык → «Привязать к Яндексу» → ввести `BRIDGE_PASSWORD`.

### Эндпоинты сервиса

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET/HEAD | `/v1.0/user/devices` | список устройств |
| POST | `/v1.0/user/devices/query` | опрос состояния |
| POST | `/v1.0/user/devices/action` | команды |
| POST | `/v1.0/user/unlink` | отвязка аккаунта |
| GET/POST | `/auth/authorize` | OAuth-авторизация |
| POST | `/auth/token` | выдача и обновление токена |
| GET | `/health` | живость сервиса |
| GET | `/debug` | диагностика (требует токен) |
| POST | `/admin/request-code` | запросить код подтверждения устройства |
| POST | `/admin/verify` | подтвердить новое устройство |

> Если Ecovacs при первом входе требует подтвердить новый вход по e-mail,
> используйте `/admin/request-code`, затем `/admin/verify` с кодом из письма.

## Проба (read-only)

`probe/` поднимает библиотеку и показывает, что видит аккаунт:

```bash
docker build -t deebot-probe ./probe
docker run --rm -it deebot-probe
```

Скрипт спрашивает e-mail и пароль, перечисляет устройства, подключается по MQTT
и в течение минуты печатает заряд, состояние и подозрительные строки лога.
**Команд роботу не отправляет.**

## Ограничения

- Один пользователь и одно устройство; многопользовательский режим не реализован.
- Нужен публичный HTTPS с валидным сертификатом.
- В Яндекс отдаются только `on_off`, `toggle` и `mode`; карты, комнаты и зоны
  в Алису не пробрасываются (они есть в библиотеке, но не в этом сервисе).
- Поддержка модели живёт в ветке PR #1869, а не в upstream: при обновлении
  библиотеки возможны конфликты.
- Голосовые фразы робот воспроизводить не умеет — в протоколе `cqyi87` нет TTS.
